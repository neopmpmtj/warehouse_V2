The big picture

One system, two workplaces

The software connects a central warehouse and a branch (branches). Same application — two workplaces.

Central warehouse

  • Holds the catalogue and the stock
  • Buys from suppliers
  • Sends goods to the branch

Branch

  • Sees what the warehouse has
  • Asks for what it needs
  • Confirms when goods arrive

The branch asks. The warehouse answers.

From item to branch stock

Example: CEM-50 — Cement 50 kg. Already in the catalogue; the circuit closes at the branch.

Every step generates structured data. The circuit only closes when the branch confirms arrival.

Internal request

The branch asks; the warehouse ships.

Branch

  • Manager approves the request
  • Offline syncs on reconnect

Warehouse

  • Short-close with a reason
  • Status becomes shipped

Branch receipt

Closed circuit: the item went catalogue → purchase → central stock → request → issue → branch stock. Every step was recorded.

Catalogue and pricing

Only the warehouse manages the catalogue.

  • Internal code does not change after creation
  • Every change is recorded

New items start inactive until ready for the global catalogue.

Procurement

From draft to closed.

No supplier price means no purchase line — the catalogue must be complete first.

Central stock

Quantity is never typed by hand.

  • Receipt (partial OK) is recorded
  • Adjust only with a reason, and only an admin

When the item is not in the catalogue

Not an order — a conversation that closes once the item enters the catalogue.

Context

Today's scenario

A central warehouse manages the master catalogue, buys from suppliers, and ships stock.

Satellite branches browse the catalogue, request items, and confirm arrivals — including offline (PWA).

Everything converges in one database: every action leaves a structured trail.

  • Catalogue + pricing — families, items, suppliers, selling and cost prices
  • Procurement + stock — purchase orders, receipts, movement ledger
  • Internal request — branch orders → shipment → branch receipt
  • Communication — request threads + Company Voice

Authorization and controls

Warehouse — purchase orders

/manage/approval-limits/

  • Admin — approves any amount
  • Manager grade 2+ — approves within EUR gross caps (own vs others)
  • Operator — never approves

Branch — internal requests

/manage/branch-approval-limits/

  • Manager — approves within per-branch caps
  • Branch admin — unlimited approval
  • Reject / short-close requires a written reason
