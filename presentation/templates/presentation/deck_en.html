Architecture

Two worlds, one system

Central warehouse

/manage/…

Admin Manager (grade 1–3) Operator
  • Item and supplier management
  • Purchase orders and approval
  • Goods receipt and stock
  • Shipment to branches
  • Request threads (warehouse side)

Satellite branches

/branch/…

Admin Manager Operator
  • Read-only catalogue (cost hidden)
  • Internal request (+ offline)
  • Request threads (missing items)
  • Branch receipt
  • Company Voice

Important: warehouse group ≠ branch role. These are independent permission circuits.

Closed circuit

From item to branch stock

Every step generates structured data. The circuit only closes when the branch confirms arrival.

Step 1

Catalogue and pricing

/manage/items/

  • Families and sub-families — two-level taxonomy
  • Item — internal code (immutable after creation), description, VAT, selling prices (retail, wholesale, special)
  • Suppliers — cost price per item; one primary supplier per item
  • Genesis — activation requires retail price > 0 and qualification
  • Audit — every change logged in ItemChangeLog

New items start inactive until ready for the global catalogue.

Step 2

Procurement

/manage/purchase-orders/

  • Draft → choose supplier, add lines with quantity and discounts
  • Validation — line rejected if supplier has no price for the item
  • Submitted → awaits financial approval
  • Approved — net/VAT/gross totals frozen at approval time
  • Received / Closed — after partial or full goods receipt

No supplier price means no purchase line — the catalogue must be complete first.

Step 3

Authorization and controls

Warehouse — purchase orders

/manage/approval-limits/

  • Admin — approves any amount
  • Manager grade 2+ — approves within EUR gross caps (own vs others)
  • Operator — never approves

Branch — internal requests

/manage/branch-approval-limits/

  • Manager — approves within per-branch caps
  • Branch admin — unlimited approval
  • Reject / short-close requires a written reason

Step 4

Central stock

/manage/goods-receipts/

  • Goods receipt — partial or full; each receipt writes StockMovement
  • Cached quantity — Item.quantity updates only via movements
  • Available = on-hand − reserved (approved requests)
  • FIFO reservation (D32) — on request approval, reserve what is on hand; incoming stock auto-allocates
  • Stock adjust — warehouse admin only, mandatory reason

Step 5

Internal request

Branch side

/branch/requests/

  1. Browse catalogue (cost hidden, stock hint)
  2. Create draft and add lines
  3. Submit → manager approves (freezes totals)
  4. Offline: drafts queued locally; sync on reconnect

Warehouse side

/manage/internal-requests/

  1. Queue of approved requests
  2. Issue goods (partial OK) — central stock decreases
  3. Short-close with reason
  4. Status becomes shipped → branch receives

Step 6

Branch receipt

/branch/receipts/

  • Branch confirms quantities received against the shipment
  • Branch stock increases via BranchStockMovement
  • Partial receipt allowed; short-close with reason (manager+)
  • Branch admin can adjust local stock

Closed circuit: the item went catalogue → purchase → central stock → request → issue → branch stock. Every step was recorded.

Circularity

When the item does not exist

A thread is a conversation, not an order. The item is born in the normal catalogue flow — never inside the thread.

Closing the human loop

Continuous feedback

Request threads

/branch/threads/ · /manage/threads/

  • States: awaiting warehouse / awaiting branch / closed
  • Only the opener closes (with reason + satisfaction)
  • Warehouse admin can force-close
  • Unread badges via ThreadReadState

Company Voice

/company-voice/

  • All staff (warehouse + branch) read and post
  • Tags: praise, concern, suggestion, wish
  • One reply sub-thread per post
  • Edit within 15 minutes; soft delete by author

Transactions generate data; conversations generate context. Both feed management.

Call to action

Start today — data compounds

  • 1 Warehouse: keep the catalogue up to date; record every receipt and shipment in the system — not on parallel paper.
  • 2 Branches: place requests via /branch/requests/; use threads for missing items; confirm receipts.
  • 3 Management: approve with care; EUR limits protect cash flow and build a decision history.
  • 4 Everyone: share feedback on Company Voice — continuous improvement needs real voices.
