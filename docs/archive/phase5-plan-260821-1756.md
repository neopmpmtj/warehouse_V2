## 1. Goal

A satellite branch browses the global catalogue (cost hidden, stock as a hint), raises a priced **Requisição interna**, and a branch manager approves it. The warehouse sees **approved** requests, ships with `GoodsIssue` (central stock down), and the branch confirms arrival against that dispatch. Branch stock is its own ledger. Out-of-stock is a **manual PO** for now; lines already have a nullable PO link so later automation can attach without a redesign.

## 3. Models (ERD)

### `branches`

**`Branch`**

- `name` — case-insensitive unique (family pattern)
- `is_active` — default True
- timestamps

**`BranchMembership`**

- `user` FK `accounts.User` `PROTECT`
- `branch` FK `PROTECT`
- `role` — `operator` \| `manager` \| `admin`
- `unique(user, branch)` — one role per user per branch
- timestamps

A user may have memberships on several branches (different roles allowed). Warehouse groups never imply branch access, and vice versa.

### `orders`

**`InternalRequest`**

- `branch` FK `PROTECT`
- `status` — see §4
- `created_by` / `submitted_by` / `approved_by` (nullable FKs)
- `submitted_at` / `approved_at` nullable
- `approved_net` / `approved_vat` / `approved_gross` — frozen at approve (`max_digits=14`, 2 dp, nullable)
- `notes`, `warehouse_notes` (blank OK)
- timestamps

**`InternalRequestLine`**

- `internal_request` FK `CASCADE`
- `item` FK `PROTECT`
- Snapshots (like PO): `description`, `internal_code`, `unit_of_measure`, `vat_rate` (fraction)
- `quantity` `Decimal(12,3)` — `> 0`, `≤ 1e9`
- `unit_price` — wholesale snapshot at **approve** (0 on draft until then, or snapshot at add-line and refresh at approve; **must match live wholesale at approve**)
- `unique(internal_request, item)` — do not merge qty
- **Seam (unused in Phase 5):** nullable `purchase_order` FK, nullable `purchase_order_line` FK
- **No line status field** — remaining issued/received qty is derived (PO pattern)

**`InternalRequestChangeLog`** / **`InternalRequestLineChangeLog`** — same shape as PO logs (`user`, `action`, `changes` JSON, `reason`, `created_at`).

**`BranchApprovalLimit`**

- One global row keyed by `role` (MVP: **`manager` only**)
- `approval_limit` / `self_approval_limit` — EUR **gross**, `≥ 0`
- `unique(role)`
- Change log like `ApprovalLimitChangeLog`
- Branch **admin** is unlimited (no row). Operator never approves.
- Edited by **warehouse admin** at `/manage/branch-approval-limits/` (not by branch staff)
- Seed (same order of magnitude as warehouse manager grade 2): self `100` / others `5_000`

### `inventory` (new)

**`GoodsIssue`**

- `internal_request` FK `PROTECT`
- `issued_by` FK `PROTECT`
- `issued_at` auto
- `reference`, `notes` blank OK

**`GoodsIssueLine`**

- `goods_issue` FK `CASCADE`
- `internal_request_line` FK `PROTECT`
- `quantity_issued` `Decimal(12,3)` `> 0`
- `unique(goods_issue, internal_request_line)`

**`BranchReceipt`**

- `goods_issue` FK `PROTECT` — parent is the dispatch/guia (lock 4)
- `received_by` FK `PROTECT`
- `received_at` auto
- `reference`, `notes`

**`BranchReceiptLine`**

- `branch_receipt` FK `CASCADE`
- `goods_issue_line` FK `PROTECT`
- `quantity_received` `Decimal(12,3)` `> 0`
- `unique(branch_receipt, goods_issue_line)`
- Reject if qty > shipped remaining on that issue line

**`BranchItemStock`**

- `branch` FK, `item` FK, `quantity` cached `Decimal(12,3)` default 0
- `unique(branch, item)`
- `CheckConstraint` quantity `≥ 0`

**`BranchStockMovement`**

- `branch`, `item`, signed `quantity`, `movement_type` (`receipt` \| `adjustment`)
- GenericForeignKey to `BranchReceipt` / adjustment (same both-or-neither constraint as warehouse `StockMovement`)
- `reason`, `created_by`, `created_at`
- Append-only; cache updated only via this ledger

Warehouse `StockMovement.Type.GOODS_ISSUE` becomes live; GFK points at `GoodsIssue`.

## 4. Status machines

Header only. Lines have quantities + optional PO FKs, not a status enum.

```text
draft → submitted → approved | rejected
draft → cancelled
approved → cancelled          (zero goods issues, reason)
approved → fulfilling | shipped
fulfilling → shipped
shipped → received | closed
received → closed
```

Skip is allowed **in the same transaction** when qty math says so (first issue that finishes the warehouse side → `shipped`; first receipt that finishes the branch side → `closed`). Do not persist `fulfilling` for a fully issued first dispatch.

| Status | Meaning |
|--------|---------|
| `draft` | Branch building the requisição |
| `submitted` | Waiting branch manager |
| `approved` | Visible to warehouse; not yet issued |
| `rejected` | Branch manager rejected (reason). Terminal. New requisição if needed. |
| `fulfilling` | At least one `GoodsIssue`; warehouse remainder still open |
| `shipped` | Warehouse done (fully issued or warehouse short-close) |
| `received` | At least one `BranchReceipt`; branch remainder still open |
| `closed` | Branch done (fully received or branch short-close) |
| `cancelled` | Voided before any goods issue |

**Who / rules**

| Action | From | Who | Extra |
|--------|------|-----|--------|
| Submit | `draft` | operator / manager / admin | ≥1 line; items active; wholesale `> 0`; branch active |
| Approve | `submitted` | manager (caps) / admin (unlimited) | Snapshot wholesale + VAT; freeze `approved_*`; show **gross** on approve UI (draft/catalog may hide money) |
| Reject | `submitted` | manager / admin | Reason required |
| Cancel | `draft` | operator / manager / admin | |
| Cancel | `approved` | manager / admin | Reason required; **zero** `GoodsIssue` rows (N1 analogue) |
| First / further issue | `approved` / `fulfilling` | warehouse `can_issue_goods` | Partial OK |
| Warehouse short-close | `approved` / `fulfilling` | warehouse **manager grade 2+ or admin** (not operator) | Reason; unshipped remainder written off; → `shipped` |
| Branch receipt | `shipped` / `received` | branch operator / manager / admin | Against a `GoodsIssue`; cannot exceed shipped remaining |
| Branch short-close | `shipped` / `received` | branch **manager / admin** (not operator) | Reason; unreceived remainder written off; → `closed` |

No cancel after the first goods issue — short-close only.

**Inactive branch (lock 9):** no new request, add/update/remove line, submit, or approve. In-flight docs stay readable; issue, branch receipt, short-close, and close still run so stock in transit is not stuck.

**Inactive item (D16):** block new lines / submit / approve if the item (or family) is inactive. Existing lines keep snapshots.

## 5. Permissions

### Branch (`branches/capabilities.py` — source of truth on the website)

| Capability | operator | manager | admin |
|------------|:--------:|:-------:|:-----:|
| Browse catalog, draft, lines, submit, cancel draft | yes | yes | yes |
| Approve / reject | no | yes (caps) | yes (unlimited) |
| Cancel approved (0 issues) | no | yes | yes |
| Branch receipt (partial) | yes | yes | yes |
| Branch short-close | no | yes | yes |
| `adjust_branch_stock` | no | no | yes |
| Create users / memberships | no | no | **not in Phase 5** |

Head office creates users and memberships in **`/admin/`** (superuser). Branch staff never get `/admin/`. The `admin` role is a shop power user, not a site administrator. A later “people at this branch” page may be granted to `admin` only; not this phase.

Self-approve: manager may approve their own submission within `self_approval_limit`; others’ requests use `approval_limit`.

### Warehouse

| Capability | Who |
|------------|-----|
| `can_issue_goods` | Same people as `can_receive_goods` (mutate closed circuit). **Own perm code** — do not overload receipt. |
| Warehouse short-close | `can_approve_purchase_order` people (manager grade 2+ / warehouse admin), not operators |
| See request queue | Warehouse groups; **`approved` and `fulfilling` only** for work. Never `submitted` / `draft`. `shipped`+ is history. |

Isolation: other-branch rows return **404**, not 403.

## 6. Services (thin views → `services.py`)

### `branches`

- `get_memberships(user)`, `get_active_branch(request)`, `set_active_branch(request, branch)`
- Middleware: `request.active_branch` from session. If membership revoked or branch inactive for **new** work → clear session, picker. Dual warehouse+branch: warehouse consoles ignore active branch.

### `orders`

- `create_internal_request`, `update_internal_request` (draft notes)
- `add_line` / `update_line` / `remove_line` — lock header (`select_for_update`); reject duplicate item; reject inactive item/family; reject `wholesale_price == 0` (lock 6) on add, submit, and approve
- `submit`, `approve`, `reject`, `cancel`
- `approve`: lock, snapshot unit prices from current `Item.wholesale_price`, compute totals with `round_money`, caps, overflow guard (N9 analogue), freeze `approved_*`
- QuerySet helpers: `.for_branch(branch)`, `.for_user_branches(user)`

### `inventory`

- `issue_goods(request, lines, user, reference="", notes="")` — lock request + items by **sorted pk** (M6); cannot issue more than on-hand or request remaining; write `GoodsIssue` + negative `GOODS_ISSUE` movements; bump header status
- `short_close_issue(request, user, reason)` — warehouse side
- `receive_at_branch(goods_issue, lines, user, …)` — lock; reject over-receipt vs that issue line’s remaining; `BranchStockMovement` + `BranchItemStock.quantity`
- `short_close_receipt(request, user, reason)` — branch side
- `adjust_branch_stock(branch, item, qty, reason, user)` — branch admin only; reason required

`on_commit` notify stubs: names only, no send (Phase 6).
