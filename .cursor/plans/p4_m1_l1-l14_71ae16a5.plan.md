- **M1** — selling prices & reorder level must be **finite and ≥ 0**. `0` is a valid selling price ("free") and a valid reorder level ("never reorder"). Negative / NaN / Infinity are rejected in the service, and guarded at the DB with `CheckConstraint`s.

- **L7 (confirm)** — PO `quantity` upper bound = `1_000_000_000` (same as inventory `_parse_decimal_quantity`). No new business rule; keeps the two parsers aligned.
- **L10 (confirm)** — remove `StockMovement.Type.INITIAL` (opening balances via `ADJUSTMENT`) and `SupplierItemPriceChangeLog.Action.DEACTIVATED/REACTIVATED` (supplier prices have no `is_active`). Migrations: no data migration needed (no rows use these values).
- **L11 (confirm)** — remove `CHANGE_GOODS_RECEIPT` (constant + `MUTATE_PERMISSIONS` entry). No receipt-edit flow is planned.
- **L13 (confirm)** — **defer** login rate limiting; document as a pre-production blocker (proxy-level or `django-axes` later). No new dependency this pass.
- **L9** — dashboard keeps `groups`; `permissions` (all codenames) only when `request.user.is_superuser` or `settings.DEBUG`.
- **L4** — VAT rate is a fraction (`line_vat = line_net * rate`), so bound `0 ≤ rate ≤ 1`.

## 1. M1 — non-negative selling prices / reorder level

**Files:** [`products/services.py`](products/services.py), [`products/models.py`](products/models.py)

Generalize the existing `_validate_cost_price` pattern into a `_validate_non_negative(value, *, field_label)` helper (or reuse it) and apply to `retail_price`, `wholesale_price`, `special_price`, `reorder_level` in both `create_item` and `update_item`. Raise a dedicated `ValidationError` with a stable `code` (e.g. `invalid_selling_price` / `invalid_reorder_level`) mirroring `InvalidCostPriceError`.

Model: add `MinValueValidator(0)` on the four fields **and** DB `CheckConstraint`s (`retail_price__gte=0`, `wholesale_price__gte=0`, `special_price__gte=0`, `reorder_level__gte=0`) — migration `products/0008`. `_save_item` already runs `full_clean`, so the validators fire on create/update.

Tests: `create_item` / `update_item` reject `-1`, `"NaN"`, `"Infinity"` for each of the four fields; accept `0`.

## 2. L1 — non-empty description

**File:** [`products/services.py`](products/services.py)

Add `description = (description or "").strip()` + required check in `create_item` (and enforce non-empty in `update_item` when `description` is passed). Raise `ValidationError("description is required.", code="description_required")`. The console already checks this; this closes the admin/CLI gap.

## 3. L2 — remove family rename

**Files:** [`products/services.py`](products/services.py), [`products/console_views.py`](products/console_views.py)

Drop `"name"` from `FAMILY_UPDATABLE_FIELDS` (leave `("is_active",)`). Remove the `if "name" in payload: fields["name"] = ...` block from `manage_family_detail`. `update_family` keeps its `is_active` handling and the `select_for_update` return value (seed relies on it).

## 4. L3 — inactive supplier/item can't get a new price

**File:** [`products/services.py`](products/services.py)

In `create_supplier_item_price`, after resolving supplier/item, assert both are active via `filter(pk=..., is_active=True).exists()` (fresh DB check, matching the procurement pattern). Raise `InactiveSupplierError` / `InactiveItemError` equivalents (add small error classes in `products` or import from a shared location — keep them local to `products/services.py`).

## 5. L4 — VAT rate range

**Files:** [`products/models.py`](products/models.py), migration `products/0009` (or fold into `0008`)

Add `CheckConstraint(condition=Q(rate__gte=0, rate__lte=1), name="vat_rate_gte_zero_lte_one")`. Optionally add `MinValueValidator(0)` / `MaxValueValidator(1)` on the field.

## 6. L5 — `line_vat` in serializer

**File:** [`procurement/console_views.py`](procurement/console_views.py)

Add `"line_vat": _dec(line.line_vat),` to `_serialize_line` (between `line_net` and `line_total`).

## 7. L6 — finite-aware console parser

**Files:** [`procurement/console_views.py`](procurement/console_views.py), [`products/console_views.py`](products/console_views.py)

Both console `_parse_decimal` helpers catch `InvalidOperation` but not NaN/Infinity. Add `if not parsed.is_finite(): raise ValidationError(f"{field_name} must be a finite number.")`. (The service parsers already do this; keep the console helpers self-contained rather than cross-importing.)

## 8. L7 — PO quantity upper bound

**File:** [`procurement/services.py`](procurement/services.py)

In `_validate_quantity`, after `value <= 0` reject, also reject `value >= Decimal("1000000000")` with `code="invalid_quantity"` ("quantity is too large"). Matches inventory's `_parse_decimal_quantity` bound.

## 9. L8 — timezone validation + middleware cleanup

**Files:** [`accounts/models.py`](accounts/models.py), [`accounts/middleware.py`](accounts/middleware.py)

- Add `User.clean()` that validates `self.timezone` against `zoneinfo.ZoneInfo`; raise `ValidationError` on unknown names. (No console user-edit form exists; this guards `/admin/` and future forms.)
- Middleware: wrap the response in `try/finally` so `timezone.deactivate()` always runs, preventing the activated timezone leaking across requests in a reused worker thread.
